# Work Report: 项目级概览与下拉项目切换

## Issue

- File: `.changes/issues/issue-002-项目级概览与下拉项目切换.md`
- ID: ISSUE-002

## Understanding

用户要先在组合层面判断项目健康度，再进入单项目的任务判断。此次只改变 UI 信息架构：项目下拉选择和项目级摘要；不改变扫描、任务事实源、详情和归档逻辑。

## Decision Log

### 用户关键决策

项目切换必须改为下拉框；“全部项目”的概览和统计必须以项目为单位，而不是任务混排。用户希望整体样式更精致、层级更清晰。

### 实现思路

组合首页使用可点击的项目管理摘要行：每行放置最关键的活跃/阻塞/待补证/高风险/知识统计及一项推荐关注任务。进入单项目后继续沿用已有的任务状态、优先级与归档判断面板，避免将两个层级混在一起。

### 放弃方案

不采用把项目统计塞进原先三列“建议先处理”卡片的方式，因为项目数量增长时仍然难以横向比较；不新增图表库，避免为基础计数引入依赖和视觉噪声。

### 合并时必须保留

项目摘要统计必须只来自已有 scan summary/cards；不可扫描和零记录项目必须保留；点击摘要行切换项目时，后续 Tab/筛选器必须使用同一个 `app.projectId`。

## Investigation

检查了 `public/index.html`、`public/app.js`、`public/style.css` 和现有跨项目 API。API 已为每个 project 返回 summary，足以完成项目级展示，无需改 server 或扫描器。

## Implementation

已调整模板和前端渲染，将 pill 切换替换为下拉选择；新增组合项目摘要和项目级统计；将视觉方向收束为深绿项目经营台账。Codex iframe 由侧车预取 loopback `/api/scan` 数据并注入，规避 opaque `about:blank` frame 偶发拒绝 fetch 的问题。侧车版本指纹现覆盖 `public/` 资源，因此常驻窗口会在 UI 更新后重建 iframe，而不会保留旧页面逻辑。

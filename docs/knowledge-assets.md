# 可复用知识资产

项目的决策、方案、架构和提示词不应该散落在对话或某次实现里。建议先从每个
项目的 Git 仓库中建立以下纯 Markdown 资产；它们可以被 Specboard 的“项目记忆”
扫描和链接，也可以被下一个项目直接引用。

```text
knowledge/
  architecture/  # 可复用架构基线
  playbooks/     # 可执行工作法与排查路径
  prompts/       # 已验证提示词与使用边界
  case-studies/  # 问题—取舍—验证—结果复盘
```

每个资产应说明：适用场景、非适用条件、关键取舍、来源证据、维护人和状态
（实验 / 已验证 / 废弃）。不要将尚未验证的一次性聊天结论包装成团队标准。

新项目可先从 `architecture/` 和 `playbooks/` 选择合适基线，再将采用、调整和
不采用理由沉淀到该项目的 `.changes/discussions/` 或 ADR。这样经验能迁移，
而不会把旧项目的假设悄悄带入新项目。

# Work Report: 重构参考图任务控制台视觉与视图

## Issue

- File: .changes/issues/issue-001-重构参考图任务控制台视觉与视图.md
- ID: ISSUE-001

## Understanding

基于用户提供的 Dashi Taskboard 截图，把已有看板调整为“项目优先、状态优先”的轻量控制台。范围只包含 `public/` 展示层和一个与新 DOM 对齐的侧车校验选择器；不调整扫描、登记、归档或真实源记录。

## Decision Log

### 用户关键决策

用户要求参考截图进行美化，并明确希望使用对应的前端设计 skill。已选择浅灰白背景、细边框、低阴影和紧凑密度，而不是延续原有深绿“经营台账”视觉。

### 实现思路

保留一套页面和已有数据模型，只重排为仪表盘、议题看板、列表视图、项目记忆四个入口。状态列严格映射 issue 的已有 status；完成率与统计来自扫描结果；缺失字段不生成虚构内容。

### 放弃方案

未实现截图中的甘特图、自动化、运行中对话和角色贡献：当前源记录没有稳定的日期区间、对话会话或角色归属事实，展示会造成误导。未引入前端框架或第三方 UI 包，避免把本地插件的简单静态页面扩大为构建链路。

### 合并时必须保留

必须保留 Markdown / OpenSpec / Git 为唯一事实源；项目下拉、筛选、搜索、详情弹窗、项目故事、项目登记与 Codex localhost iframe 预取/注入流程继续可用。侧车对新页面以 `.completion-copy h1` 做加载检查，不得恢复对已删除 `#project-name` 的依赖。

## Investigation

读取了 `public/index.html`、`public/app.js`、`public/style.css`、`scripts/codex-sidecar.mjs`、测试和三个参考截图。确认现有扫描数据包含创建者、创建时间、进度、风险、阻塞、归档检查和任务详情，足以支持三种真实任务视图。

## Implementation

重写页面骨架与 CSS；新增状态分组、完成度、看板列、可折叠列表组和项目记忆面板；任务卡仍复用 `data-card-key` 打开原详情。项目摘要说明在仪表盘中截断，防止 README 大段文本压垮首屏。调整侧车加载后检查的标题选择器。

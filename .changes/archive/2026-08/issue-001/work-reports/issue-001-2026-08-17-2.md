# Work Report: 修复项目故事预览与刷新交互

## Issue

- File: .changes/issues/issue-001-修复项目故事预览与刷新交互.md
- ID: ISSUE-001

## Understanding

修复项目故事阅读与刷新反馈两个稳定复现的交互缺陷。范围限定为前端展示层；故事的生成内容与服务端扫描语义不变。

## Decision Log

### 用户关键决策

用户明确反馈“项目故事点开显示的 markdown 预览效果不好，而且再次点击无法关闭；刷新按钮无法点击”。用户期待在看板内阅读并能够关闭，而不是重新设计项目故事内容。

### 实现思路

保留服务器 `/api/narrative` 返回原始 Markdown 的契约，在前端转为受控 dialog 和轻量、转义后的 Markdown 展示；这样既提供可读预览，也保留“查看原始 Markdown”出口。刷新改为明确强制请求 `/api/scan`，复用已有渲染逻辑。

### 放弃方案

未新增第三方 Markdown 库或构建步骤：项目是本地零依赖静态页面，当前故事生成的 Markdown 仅需标题、段落、列表、引用、代码和基础行内格式。未把故事生成为 HTML 端点，避免更改现有可分享的原始 Markdown API。

### 合并时必须保留

保留 `/api/narrative?project=<project-id>` 返回原始 Markdown；预览中的“查看原始 Markdown”必须带同一 URL。保留 Codex iframe 的 managed bootstrap：首屏仍可消费预取数据，手动刷新必须绕过该快照强制扫描。刷新期间按钮禁用，最终无论成功失败都恢复可点击。

## Investigation

读取了顶栏 HTML、`load()`、故事链接与服务端 narrative 路由。发现故事是 `target=_blank` 普通链接；服务端已可稳定返回 Markdown。浏览器验证 `/api/scan` 正常、一次扫描约 0.7 秒，旧刷新逻辑无加载/错误反馈。

## Implementation

将故事链接替换为按钮，新增 story dialog、关闭按钮、原文链接和安全的轻量 Markdown renderer。`load({ force })` 现在处理 refresh 按钮的禁用/恢复与“刷新中”标签；`refreshBoard()` 强制 `cache: no-store` 请求 scan，失败时提供可见错误。补齐窄屏故事弹窗样式。

## Bug Details

### Reproduction

本机页面顶部点击项目故事和刷新即可稳定复现。

### Root Cause

项目故事使用普通 anchor 且 `target=_blank`，没有应用内状态或关闭控件。

### Fix

改为应用内 dialog 预览，提供关闭、再次打开和查看原文；刷新显式绕过 bootstrap 和缓存，并补加载/错误状态。

### Regression Test

浏览器手工覆盖故事打开、关闭、再次打开、单项目 URL、刷新状态；Node 测试保持全量通过。

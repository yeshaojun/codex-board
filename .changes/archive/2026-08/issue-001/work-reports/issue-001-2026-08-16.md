## Understanding

用户需要的不只是任务列表，还包括 AI 讨论后的方案、计划、架构取舍，以及一份可被非技术人员阅读、可被技术人员复盘的项目叙事。现有 `.changes` 已包含 issue、session notes、ADR、work report、test report 与 merge report，但缺少统一入口与可重建视图。

## Decision Log

- 采用本地优先、源文件优先的独立工具：`.changes`、OpenSpec 和 Git 仍为事实源，Specboard 不维护第二套可漂移任务库。
- 将讨论与计划设置为一等卡片：新记录分别写入 `.changes/discussions/` 与 `.changes/plans/`，不保存原始聊天记录。
- 项目故事由确定性扫描器产生带来源的初稿；它标注待补证，不让模型推断缺失的完成事实。
- 第一版不 fork 现有 Taskboard 的 UI 注入路径，避免依赖内部桌面实现；先以独立 localhost 网页和 Codex Skill 联动。

## Local Availability and Codex Installation

页面在一次执行后无法访问的原因是 server 作为临时子进程退出，而非扫描或 UI 本身故障。为使首个 Cowork 看板可长期使用，新增受版本控制的 launchd 模板和安装/移除脚本：它仅监听 `127.0.0.1:47932`，登录后自动恢复，日志写入用户的 `~/Library/Logs/`。

Codex 插件不应依赖 root-owned 的默认 personal marketplace。改为在 Specboard 仓库内提供显式本地 marketplace（`.agents/plugins/marketplace.json`），由 `codex plugin marketplace add /Users/andy/plugins/loctek-specboard` 注册，随后可安装 `loctek-specboard@loctek-local`。这不会更改默认个人 Marketplace 的权限或文件。

## Control Room Upgrade

用户明确要求看板首先服务于“工作判断”，而不是仅展示 Markdown 卡片。因此将原 Kanban 替换为五个只读 Tab：概览、任务、方案与计划、架构、决策。

- 任务列表新增创建时间、创建者、最近更新、风险和归档前检查状态。
- issue 详情按源文件机械提取“要做什么”“验收进度”“被阻塞”，并关联 work/merge/PR、test 等证据。
- 归档提示严格区分：未完成状态/验收/显式阻塞属于阻塞，缺少 test 或执行记录属于待补证；两者均不替代实际的 `archive.mjs --dry-run`。
- 后续建议按固定顺序生成：先解除阻塞，再推进第一项未完成验收，随后补验证与执行记录。工具不会擅自将任务改成 done。

对应实现位于 `src/lib.mjs` 的 issue detail/归档评估，以及 `public/` 的控制台 UI；测试新增阻塞任务与归档建议断言。

## Cross-project Sidebar Integration

用户确认最有价值的入口是 Codex 左侧栏中的跨项目看板，而不是一个绑定单仓库的 localhost 页面。第二次迭代因此加入本机 `projects.json` 注册表，服务同时扫描所有登记的 `.changes` / OpenSpec 项目；前端在卡片和详情中保留项目标签，复合键使用 `<project>::<record>`，不把不同项目同名 issue 混为一条。

Codex Plugin/Skill 本身不能声明左侧导航页，故用户接受参考 Dashi 的非官方 UI 兼容方式。实现位于 `inject/specboard.user.js`、`scripts/codex-sidecar.mjs` 和 `scripts/codex-cdp.mjs`：`npm run codex` 只启动一个独立 profile 的 ChatGPT/Codex 窗口，专用 CDP 仅监听 `127.0.0.1:9232`，通过运行时 DOM 注入 `Specboard` 按钮和 loopback iframe。它不修改 app bundle、不读取聊天内容或凭据、不扫描现有 Codex 窗口；watch 进程负责在 renderer 重载后重挂入口。

这个集成是兼容层而非官方扩展 API，Codex UI 更新后可能需要调整 selector。已排除的替代方案是仅提供 Skill/plugin + 浏览器 URL：它无法满足从 Codex 左栏直接打开跨项目控制台的核心诉求。

## Embedded Portfolio Refresh Reliability

侧栏的 iframe 首次嵌入使用 `about:blank`，再由受限于 loopback 的 CDP 写入页面内容，以避开 Codex `app://` 对 localhost iframe 的 CSP 限制。多项目同步完成后，旧实现只判断 `app.portfolio` 是否存在；该变量可能来自旧扫描，造成 UI 偶发仍显示旧项目组合或一直停留在加载提示。

- 嵌入文档不再保留外部 `app.js`，仅由侧车注入一次受控脚本，避免两个异步 `load()` 竞争渲染。
- 前端脚本以 IIFE 隔离词法变量，并暴露 `window.__loctekSpecboardLoad`；这避免 CDP 覆盖 iframe 文档时保留旧全局 `const` 而使下一次脚本初始化静默失败。
- 侧车显式等待该加载函数完成，并以 `/api/projects` 的登记数量核验 iframe 的项目 pill 数；只有核验成功才关闭加载状态。
- CDP 命令支持本次嵌入扫描所需的较长超时；常规命令仍使用 15 秒默认值。

真实专用 Codex 窗口验证结果：入口存在、页面可见且已加载，标题为“跨 5 个项目的 Loctek / OpenSpec 控制台”，项目切换包含 `Loctek AI Cowork`、`demo`、`test_cluade`、`经验沉淀`、`openmetadata`，无页面错误。

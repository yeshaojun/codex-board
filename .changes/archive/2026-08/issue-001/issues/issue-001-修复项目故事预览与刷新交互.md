# 修复项目故事预览与刷新交互

## 现象

点击“项目故事”会直接打开浏览器原始 Markdown 页面，阅读样式不足；切换或再次点击无法在看板内关闭。用户还反馈“刷新”按钮无效。

## 期望行为

项目故事应在看板内以易阅读的预览弹窗打开，可显式关闭，并可选择查看原始 Markdown；刷新应显示进行中状态、重新从本机扫描数据并更新页面。

## 复现信息

本机 `http://127.0.0.1:47932/`：点击项目故事会导航至 `/api/narrative`（服务返回 `text/markdown`），而不是应用内预览。刷新旧实现只调用 `load()`；在 Codex 嵌入环境中该调用会优先使用已经消费或不再存在的 bootstrap 状态，且没有任何加载/错误反馈。

## 已知事实

`/api/narrative?project=cowork` 正常返回完整 Markdown；`/api/scan` 正常返回数据且单次扫描约 0.7 秒。刷新按钮存在 click 监听，但没有禁用态、加载提示或失败显示。浏览器复现时无控制台错误。

## 初始假设

- [x] 原项目故事是带 `target=_blank` 的普通链接，因此由浏览器直接渲染 Markdown，无法提供关闭行为。
- [x] 刷新未强制从 `/api/scan` 请求新数据，且没有处理交互反馈；在嵌入页面中尤其难以判断是否执行。

## 排查计划

将故事入口改为按钮，新增受控 dialog 和安全的轻量 Markdown 渲染；刷新改为显式强制 scan、加载态及错误视图。随后以浏览器点击验证故事打开/关闭、项目选择后的来源参数以及刷新后的时间变化。

## 修复边界

只修项目故事预览与刷新交互。不会重写 `generateNarrative`，不会新建 Markdown 文件或引入第三方 Markdown 依赖，也不改登记、扫描、归档与 Codex iframe 协议。

## 验收标准

- [x] 点击项目故事显示有层级的应用内预览，能通过关闭按钮关闭。
- [x] 预览的“查看原始 Markdown”仍可打开原始内容，且选择单项目时携带正确 project 参数。
- [x] 点击刷新显示刷新中，强制重新扫描并更新页面；失败时显示明确错误。
- [x] 原始症状被修复或根因被明确定位。
- [x] 修复不改变必须保留的既有行为。

## 被阻塞

无，可以立即开始；如果缺少复现信息或生产证据，请改为 HITL 并写明。

## 影响范围

影响所有通过 standalone 页面或 Codex 左栏使用 Specboard 的用户；稳定复现；入口为顶栏“项目故事”和“刷新”。

# 项目级概览与下拉项目切换

## 背景

当前首页先把所有项目中的任务混合成一组“建议先处理 / 当前阻塞 / 待补证”卡片，项目切换使用多个 pill。用户难以先判断哪个项目整体需要关注；项目数量继续增加后，pill 也会挤占页面空间。

## 目标

将首页升级为项目级经营视图：用户先看到每个项目的任务规模、阻塞、待补证、高风险任务和知识沉淀，再进入一个项目处理具体问题。

## 非目标

- 不创建任务数据库，不改变 `.changes`、OpenSpec、Git 的事实源地位。
- 不改变 issue 详情、归档判断或跨项目复合卡片键。
- 不实现新的项目权限、排序持久化或任务编辑能力。

## 要构建什么

- 将项目 pill 改为原生下拉选择：包括“全部项目”与每个可扫描项目，无法扫描的项目明确标记并禁用。
- 在“全部项目 / 概览”下按项目渲染一行管理摘要，固定展示活跃任务、阻塞、归档待补证、高风险和知识记录，并展示一个推荐关注任务。
- 点击项目摘要行或使用下拉框后，切换至该项目；单项目概览保留现有任务状态与具体判断面板。
- 提升头部、项目选择器、项目摘要行的层级与状态视觉，使其适合日常项目经营判断。

## 验收标准

- [x] 页面仅显示一个项目下拉选择入口，能够切换“全部项目”和任一可扫描项目。
- [x] 全部项目的概览按项目展示，而不是把所有任务混排；每个可扫描项目显示项目级任务统计。
- [x] 点击项目摘要行可进入对应单项目概览，状态、任务数和 Tab 内容同步更新。
- [x] 零记录项目仍展示为零统计；无法扫描项目仍显示原因且不阻塞其余项目。
- [x] 独立 localhost 页面与 Codex iframe 入口均可完成加载。

## 被阻塞

无，可以立即开始。

## 影响范围

仅 `public/index.html`、`public/app.js`、`public/style.css` 与本 issue 的工作记录；不修改扫描器、服务 API 或被扫描项目。

## 预计改动区域

- `public/index.html`
- `public/app.js`
- `public/style.css`

## 必须保留的行为

- 组合统计仍只聚合可扫描项目；不可扫描项目不让整个页面失败。
- 所有任务详情仍保留所属项目、来源路径、Git 作者、阻塞和证据提示。
- Codex iframe 仍由侧车控制加载，且只连接 loopback 服务。

## 测试计划

- 运行语法检查与 `npm test`。
- 以 `http://127.0.0.1:47932/` 的真实 5 项目组合检查下拉选择、项目级统计和项目切换。
- 通过 CDP 检查 Codex 专用窗口内 iframe 的标题、下拉选项和项目摘要数。

## 回滚考虑

回退三个 `public/` 文件即可恢复原有 pill 与混合卡片概览；源记录和项目注册表不受影响。
